# 丙组第二次进度：跨组联调与准确性、速度记录 · 2026-11-22

## 仓库现状与本次对齐

甲组已完成成本栅格读取、NoData 校验和地图坐标与行列号换算；乙组已完成可配置的 8 邻域代价规则、逐段明细及手算金标准；丁组已完成可安装的 QGIS 插件、JSON 导入、网格点选、Dijkstra / A* 切换和路径展示。本次丙组在这些已提交接口上联调，不另造输入或代价规则。

第一周丙组默认是“两格均值、禁止切角”，乙组默认是“进入格成本、允许切角”，导致同一条路的成本不一致。现在 `find_path` 与乙组 `CostConfig` 默认值对齐；`contract.shortest_path` 直接调用乙组 `neighbor_steps` 并执行真实搜索，再使用乙组 `path_step_details` 返回逐段明细。保留 `cost_mode="average"`、`allow_corner_cutting=False` 等开关以供课程规则最终确认后切换。当前默认值是团队联调口径，并非老师已确认的最终公式。

丁组插件调用 `find_path` 的位置不需改参数即可使用新默认值。其旧演示的 10×10 栅格从零起始 `(2,0)` 到 `(4,8)`，在新默认口径下搜索结果为 **51.84062043**、格网长度 **11.89949494**，会穿过第 8 行的障碍通道。原 README 的 **55.60** 属于旧规则历史演示，不可与本次结果混用；仍需丁组在 QGIS 实机重验截图。当前 QGIS 窗口只在网格内展示路径，还没有真实地图画布上的矢量 LineString 和端点图层。

窗口的不可通行格显示和点选校验也已与乙组默认规则对齐：NoData 与非正值都显示为不可通行，避免导入含 0 的 JSON 后把不能走的格子误选为起终点。

## 准确性与跨组接口

| 案例 | 乙组手算期望 | 丙组 Dijkstra / A* |
| --- | ---: | ---: |
| 乙组无障碍 4×4，默认进入格口径 | `14√2 = 19.79898987` | 一致，路径 `(0,0)→(1,1)→(2,2)→(3,3)` |
| 同一 4×4，均值口径 | `14.5√2 = 20.50609665` | 一致 |
| 甲组含 NoData 的 4×4 | `23+4√2 = 28.65685425` | 一致，绕开 `(1,1)` |
| 2×2，斜向系数改为 4 | 正交两步成本 `3` | 一致，避开成本为 `4` 的斜步 |

上述结果既验证独立 `find_path`，也验证 `contract.shortest_path` 的真实接口及逐段累计字段。保留第一周独立 Bellman-Ford 随机小网格对照，明确传入第一周均值与禁切角配置；测试因此同时覆盖两种口径。`python -m unittest discover -s tests -q` 在 Windows / Python 3.8.8 上运行 **83 项，全部通过**。乙组 `Cell` 别名在 Python 3.8 的运行时兼容问题已修复。

## 速度与规模

命令：`python benchmarks/run.py --output benchmarks/week2-2026-11-22.json`。随机格固定种子 `20261116`，成本 1–9、约 5% 障碍；计时只覆盖搜索和回溯，不含栅格生成、压平、QGIS 渲染。单次本机运行、未预热，速度仅供课程对照。完整数据含扩展节点和路径节点，见 [JSON 记录](../benchmarks/week2-2026-11-22.json)。

| 格网 | 场景 | Dijkstra 最小成本 / 耗时 | A* 最小成本 / 耗时 |
| --- | --- | ---: | ---: |
| 100² | 均一 | 140.0071 / 46.9 ms | 140.0071 / 1.1 ms |
| 100² | 随机 | 406.0732 / 48.2 ms | 406.0732 / 48.3 ms |
| 500² | 均一 | 705.6926 / 1244.9 ms | 705.6926 / 5.0 ms |
| 500² | 随机 | 1917.8145 / 1221.8 ms | 1917.8145 / 1248.4 ms |
| 1000² | 均一 | 1412.7993 / 5238.7 ms | 1412.7993 / 9.7 ms |
| 1000² | 随机 | 3869.1143 / 5263.0 ms | 3869.1143 / 5497.9 ms |

两种算法在每组栅格上给出相同最小总成本。均一栅格的启发式指向终点，A* 少扩展大量格子；随机栅格的最小成本下界较弱，A* 与 Dijkstra 时间接近。不能据此承诺 A* 对所有数据都更快。
